# Быстрый старт

🌐 **Язык:** Русский · [English](QUICKSTART.md)

[← README](README.ru.md)

## 1. Создайте общий репозиторий

Создайте, например, `username/my-ai-context` на GitHub. Скопируйте [PROJECTS.ru.md](PROJECTS.ru.md) в корень и переименуйте в `PROJECTS.md`. Скопируйте папку [projects/example-project/](projects/example-project/) целиком в `projects/` своего репозитория.

```text
my-ai-context/
├── PROJECTS.md
└── projects/
    ├── project-one/
    │   ├── PROJECT.md
    │   ├── CONTEXT.md
    │   └── INSTRUCTIONS.md
    └── project-two/
        ├── PROJECT.md
        ├── CONTEXT.md
        └── INSTRUCTIONS.md
```

## 2. Переименуйте папку шаблона

Вместо `example-project` укажите понятное уникальное название папки, например `project-one`. Используйте только три файла выбранного языка: английские `PROJECT.md`, `CONTEXT.md`, `INSTRUCTIONS.md` или русские `PROJECT.ru.md`, `CONTEXT.ru.md`, `INSTRUCTIONS.ru.md` (в пользовательском репозитории уберите `.ru` из имён). Лишние языковые версии можно удалить.

Заполните файлы с помощью AI, проверьте результат и добавьте строку в `PROJECTS.md` с названием, описанием и точным путём, например `projects/project-one/`.

## 3. Подключите GitHub

Настройте доступ в нужном AI-клиенте: [ChatGPT](platforms/chatgpt/chatgpt.ru.md), [Claude](platforms/claude/claude.ru.md), [Cursor](platforms/cursor/cursor.ru.md), [Codex](platforms/codex/codex.ru.md). Подойдёт поддерживаемая интеграция или MCP; можно передать файлы вручную. Проверьте, что AI действительно может прочитать выбранные файлы. Для записи могут потребоваться дополнительные разрешения.

## 4. Создайте проект в AI-клиенте

В ChatGPT создайте отдельный **Project** для `project-one` (в Claude — **Project**, в других клиентах — аналогичное рабочее пространство, если доступно). Открывайте новые чаты **внутри этого проекта**: так его постоянные инструкции будут применяться к новым беседам.

## 5. Настройте Project Instructions

Откройте **Project Instructions** созданного AI-проекта. Это **точка входа**: здесь указываются GitHub-репозиторий, папка проекта и проверка правильного контекста. Правила работы над проектом храните в `INSTRUCTIONS.md` внутри этой папки.

Скопируйте и заполните:

```text
Проект:
- Репозиторий GitHub: username/my-ai-context
- Директория: projects/project-one/
- Ожидаемое название в PROJECT.md: [название проекта]

При начале нового чата:
1. Прочитай PROJECT.md, CONTEXT.md и INSTRUCTIONS.md только
   из указанной директории GitHub.
2. Проверь, что все три файла прочитаны, а название в PROJECT.md
   совпадает с ожидаемым. Если путь не задан, файл недоступен
   или название не совпало — сообщи об этом и попроси уточнить.
   Не угадывай папку и не подменяй контекст другим проектом.
3. Кратко сообщи, какой репозиторий, директорию и название
   проекта ты действительно проверил.
4. Следуй правилам из прочитанного INSTRUCTIONS.md.
   Если GitHub недоступен, попроси предоставить файлы вручную;
   не утверждай, что прочитал их.
```

**Роль AI (необязательно).** Если нужна определённая помощь, добавьте в Project Instructions своё пожелание: например, «Помогай проектировать архитектуру, писать код и находить ошибки». Лучше описывать конкретные задачи и результат. Если задачи разные, роль можно указывать прямо в чате.

Название проекта сначала заполните в `PROJECT.md` (шаг 2). Оно должно совпадать с ожидаемым названием в инструкции, но может отличаться от имени папки и AI-проекта.

**Важно:** Project Instructions не подключают GitHub автоматически и не обеспечивают техническую изоляцию. Проверьте, что AI действительно прочитал нужные файлы. Если постоянных инструкций нет, вставьте этот текст первым сообщением нового чата.

## 6. Работайте и обновляйте контекст

После значимого этапа попросите AI предложить изменения `projects/project-one/CONTEXT.md`. Проверьте и подтвердите перед записью. Не перечитывайте другие проекты и не сохраняйте полную переписку.

## 7. Продолжайте работу в другом AI-чате

Откройте AI-проект с тем же настроенным репозиторием и путём. Попросите загрузить свежие файлы и назвать их точные пути. Если настройки не переносятся между платформами, повторите инструкцию из шага 5. Реестр `PROJECTS.md` нужен для обзора проектов, **не для обязательного поиска при каждом старте**.

## 8. Добавляйте проекты

Копируйте `projects/example-project/` для нового проекта, переименовывайте папку, заполняйте три файла и добавляйте строку в `PROJECTS.md`. Для каждого AI-проекта задавайте соответствующий путь. [Дополнительные файлы](optional/) при необходимости размещайте внутри его папки.

**Безопасность:** не сохраняйте секреты. Папки внутри одного репозитория не разделяют права доступа; для разных уровней доступа используйте отдельные репозитории.
