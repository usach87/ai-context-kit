# Быстрый старт: несколько проектов в одном репозитории

🌐 **Язык:** Русский · [English](QUICKSTART.md)

[← Описание AI Context Kit](README.ru.md)

Один GitHub-репозиторий хранит контекст нескольких проектов. В каждом AI-чате выбирается **один активный проект**, и помощник читает файлы только из его папки.

## 1. Создайте общий репозиторий

Создайте, например, `username/my-ai-context` в GitHub. Для конфиденциальных проектов используйте закрытый репозиторий. В корень скопируйте [PROJECTS.ru.md](template/PROJECTS.ru.md) и переименуйте в **PROJECTS.md**.

Структура:

```text
my-ai-context/
├── PROJECTS.md
└── projects/
    ├── family-app/
    │   ├── PROJECT.md
    │   ├── CONTEXT.md
    │   └── INSTRUCTIONS.md
    └── tea-business/
        ├── PROJECT.md
        ├── CONTEXT.md
        └── INSTRUCTIONS.md
```

`PROJECTS.md` — короткий реестр названий, ID и путей. Он не должен содержать подробный контекст всех проектов.

## 2. Создайте первый проект

Выберите постоянный ID латиницей, например `family-app`. Создайте папку `projects/family-app/`. Скопируйте туда три русских шаблона и **уберите `.ru` из имён**:

- [PROJECT.ru.md](template/PROJECT.ru.md) → `projects/family-app/PROJECT.md` — цели и границы.
- [CONTEXT.ru.md](template/CONTEXT.ru.md) → `projects/family-app/CONTEXT.md` — актуальное состояние.
- [INSTRUCTIONS.ru.md](template/INSTRUCTIONS.ru.md) → `projects/family-app/INSTRUCTIONS.md` — правила AI.

Можно использовать [английские шаблоны](template/PROJECT.md) с теми же итоговыми именами. Добавьте строку с ID, названием, описанием и директорией в `PROJECTS.md`.

Попросите AI помочь заполнить файлы, не придумывая фактов. Сначала проверьте предложенные изменения.

## 3. Подключите AI к GitHub

У каждой платформы свои настройки: [ChatGPT](platforms/chatgpt/chatgpt.ru.md), [Claude](platforms/claude/claude.ru.md), [Cursor](platforms/cursor/cursor.ru.md), [Codex](platforms/codex/codex.ru.md).

Подойдёт доступная GitHub-интеграция, коннектор или MCP. Отдельный MCP-сервер **не обязателен**. Проверьте фактический доступ к нужной папке. Возможность записи зависит от клиента и разрешений. Если GitHub недоступен, передавайте три файла выбранного проекта вручную.

## 4. Закрепите путь за AI-проектом или чатом

Если AI-клиент поддерживает отдельные проекты и постоянные инструкции, создайте там проект «Family App» и добавьте:

> Общий GitHub-репозиторий: `username/my-ai-context`. Активный проект: `family-app`. Путь: `projects/family-app/`. В начале новой сессии прочитай `PROJECT.md`, `CONTEXT.md` и `INSTRUCTIONS.md` **только из этой папки**. Работай и предлагай обновления только для этого проекта. Если файлы недоступны, скажи об этом; не выдумывай содержимое.

Замените репозиторий и ID на свои. Для другого AI-проекта укажите другую папку. **Постоянные инструкции не подключают GitHub сами по себе**: доступ к файлам нужно настроить отдельно. Если клиент не поддерживает такие инструкции, отправьте этот текст первым сообщением нового чата.

## 5. Работайте и сохраняйте изменения

После значимого этапа попросите AI предложить обновление **`projects/family-app/CONTEXT.md`**. Проверьте и подтвердите его перед записью в GitHub. Не сохраняйте полную историю переписки и не загружайте другие проекты без необходимости.

## 6. Перейдите в другой AI-чат

Если активный проект уже закреплён в настройках AI-клиента, попросите: «Загрузи актуальный контекст моего проекта из GitHub и продолжим».

Иначе используйте явный запрос:

> Открой `username/my-ai-context`, активный проект `family-app` по пути `projects/family-app/`. Прочитай три файла проекта и кратко расскажи о текущем состоянии и следующем шаге. Другие проекты не загружай. Если доступ отсутствует, скажи об этом.

Если вы помните только название, AI может найти нужный путь в `PROJECTS.md`. При неоднозначности он должен спросить, какой проект выбрать. **Само название чата не гарантирует автоматического выбора папки.** Полная история чатов между платформами не синхронизируется.

## 7. Добавьте следующие проекты

Для каждого проекта создавайте отдельную папку с теми же тремя файлами и добавляйте строку в `PROJECTS.md`. Не создавайте общие `CONTEXT.md` или `INSTRUCTIONS.md` в корне: они могут смешать контекст разных проектов.

При необходимости используйте [дополнительные шаблоны](optional/) внутри папки конкретного проекта: `DECISIONS.md`, `TASKS.md`, `SOURCES.md`.

## Безопасность

Не сохраняйте пароли, токены и секреты. Для чувствительной информации используйте закрытый репозиторий и минимально необходимые права. Если проекты требуют разных уровней доступа, лучше хранить их в отдельных репозиториях: папки одного репозитория сами по себе не обеспечивают изоляцию прав GitHub.
